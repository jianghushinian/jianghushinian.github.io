引言

Go 的并发原语让构建流式数据处理流水线变得轻而易举，这类流水线能够高效利用 I/O 和多个 CPU。本文给出了此类流水线的示例，重点剖析了操作失败时出现的微妙问题，并介绍了干净利落地处理失败的技术。

什么是流水线？

Go 中并没有关于流水线的正式定义；它只是众多并发程序中的一种。简单来说，流水线是由 channel 连接起来的一系列阶段（stage），每个阶段都是一组运行同一函数的 goroutines。在每个阶段中，goroutines 会：

  • 通过入站（inbound）channel 从上游（upstream）接收值
  • 对这些数据执行某种函数操作，通常会生成新的值
  • 通过出站（outbound）channel 将值发送到下游（downstream）

每个阶段可以有任意数量的入站和出站 channel，但第一个阶段和最后一个阶段分别只有出站和入站 channel。第一个阶段有时被称为源（source）或生产者（producer）；最后一个阶段则被称为接收端（sink）或消费者（consumer）。

我们先从一个简单的示例流水线开始，讲解相关思想和技术。稍后，再给出一个更贴近实际的例子。

扇出、扇入

多个函数可以从同一个 channel 读取数据，直到该 channel 关闭；这被称为扇出（fan-out）。它提供了一种在一组 worker 之间分配工作的方法，从而并行利用 CPU 和 I/O。

一个函数可以从多个输入读取数据，并通过将输入 channel 多路复用到单个 channel 上来持续处理，直到所有输入都关闭，而这个输出 channel 会在所有输入关闭后关闭。这被称为扇入（fan-in）。

提前停止

我们的流水线函数遵循一个模式：

  • 各阶段在所有发送操作完成后关闭自己的出站 channel。
  • 各阶段持续从入站 channel 接收值，直到这些 channel 关闭。

这个模式让每个接收阶段都能写成 range 循环，并确保一旦所有值成功发送到下游，所有 goroutines 都会退出。

但在真实的流水线中，阶段并不总能接收全部入站值。有时这是有意为之：接收方可能只需要一部分值就能继续推进。更常见的情况是，某个阶段因为某个入站值代表上游阶段的错误而提前退出。无论哪种情况，接收方都不应被迫等待剩余的值到达，而且我们希望上游阶段停止生产下游不再需要的值。

在我们的示例流水线中，如果某个阶段未能消费全部入站值，那么尝试发送这些值的 goroutines 将永久阻塞：

这是一种资源泄漏：goroutines 会占用内存和运行时资源，goroutine 栈中的堆引用还会阻止数据被垃圾回收。Goroutines 不会被垃圾回收；它们必须自行退出。

因此，我们需要提供一种方式，让下游阶段告诉发送方它们将停止接收输入。

显式取消

当 main 决定不接收 out 中的全部值就退出时，它必须告诉上游阶段的 goroutines 放弃它们正在尝试发送的值。为此，它在一个名为 done 的 channel 上发送值。由于可能存在两个被阻塞的发送方，它发送两个值：

发送方 goroutines 会把发送操作替换为 select 语句，该语句要么在 out 上的发送成功时继续，要么在从 done 接收到值时继续。done 的值类型是空结构体，因为这个值本身并不重要：真正指示应放弃 out 上发送操作的是接收事件。output goroutines 会继续在入站 channel c 上循环，因此上游阶段不会被阻塞。（稍后我们会讨论如何让这个循环提前返回。）

这种方法有个问题：每个下游接收方都需要知道可能被阻塞的上游发送方的数量，并在提前返回时设法通知这些发送方。跟踪这些计数既繁琐又容易出错。

我们需要一种方式，告诉数量未知且无上限的 goroutines 停止向下游发送值。在 Go 中，我们可以通过关闭 channel 来做到这一点，因为对已关闭 channel 的接收操作总是可以立即进行，并返回元素类型的零值。

这意味着 main 只需关闭 done channel 就能解除所有发送方的阻塞。这次关闭实际上就是向所有发送方广播信号。我们扩展每个流水线函数，使其接受 done 作为参数，并通过 defer 语句安排关闭操作，这样 main 的所有返回路径都会通知流水线各阶段退出。

现在，流水线的每个阶段都可以在 done 关闭后立即返回。merge 中的 output 例程无需排空入站 channel 就可以返回，因为它知道上游发送方 sq 在 done 关闭时会停止尝试发送。output 通过 defer 语句确保在所有返回路径上都会调用 wg.Done：

以下是构建流水线的指导原则：

  • 各阶段在所有发送操作完成后关闭自己的出站 channel。
  • 各阶段持续从入站 channel 接收值，直到这些 channel 关闭或发送方被解除阻塞。

流水线要么通过确保缓冲区足以容纳所有发送的值来解除发送方的阻塞，要么在接收方可能放弃 channel 时显式通知发送方。

parallel.go 中的 MD5All 实现会为每个文件启动一个新的 goroutine。在包含大量大文件的目录中，这可能分配出比机器可用内存更多的内存。

结语

本文介绍了在 Go 中构建流式数据流水线的技术。处理此类流水线中的失败颇为棘手，因为流水线中的每个阶段都可能阻塞在向下游发送值上，而下游阶段可能已不再关心传入的数据。我们展示了关闭 channel 如何向流水线启动的所有 goroutines 广播“done”信号，并定义了正确构建流水线的指导原则。
