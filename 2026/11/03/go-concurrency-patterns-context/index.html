引言

在 Go 服务器中，每个传入请求都由独立的 goroutine 处理。请求处理程序通常会启动额外的 goroutine 来访问数据库、RPC 服务等后端。处理某个请求的一组 goroutine 通常需要访问请求级的值，例如终端用户的身份、授权令牌以及请求的截止时间。当请求被取消或超时时，处理该请求的所有 goroutine 都应迅速退出，以便系统回收它们正在使用的资源。

在 Google，我们开发了 context 包，它可以轻松地将请求级的值、取消信号和截止时间跨 API 边界传递给处理请求所涉及的所有 goroutine。该包现已作为 context 公开提供。本文介绍如何使用该包，并给出一个完整可运行的示例。

Done 方法返回一个 channel，它充当取消信号，通知所有代表该 Context 执行工作的函数：一旦该 channel 关闭，这些函数就应放弃手头的工作并返回。Err 方法返回一个错误，说明 Context 被取消的原因。《Pipelines and Cancellation》一文更详细地讨论了 Done channel 惯用法。

Context 并没有 Cancel 方法，原因与 Done channel 只能接收相同：接收取消信号的函数通常并非发送信号的那一方。特别是，当父操作启动子操作的 goroutine 时，这些子操作不应能够取消父操作。相反，WithCancel 函数（下文介绍）提供了一种取消新的 Context 值的方法。

Context 可以安全地被多个 goroutine 同时使用。代码可以把同一个 Context 传给任意数量的 goroutine，并通过取消该 Context 来向它们全部发出信号。

Deadline 方法让函数能够判断自己是否应该开始工作；如果剩余时间太少，可能就不值得做了。代码也可以使用截止时间来为 I/O 操作设置超时。

Value 允许 Context 携带请求级数据。这些数据必须能安全地被多个 goroutine 同时使用。

派生 Context

context 包提供了从现有 Context 值派生出新 Context 值的函数。这些值构成一棵树：当某个 Context 被取消时，由它派生的所有 Contexts 也会被取消。

让现有代码适配 Context

许多服务器框架提供用于携带请求级值的包和类型。我们可以定义 Context 接口的新实现，在使用现有框架的代码和期望 Context 参数的代码之间架起桥梁。

例如，Gorilla 的 github.com/gorilla/context 包通过提供从 HTTP 请求到键值对的映射，让处理程序能够把数据与传入请求关联起来。在 gorilla.go 中，我们提供了一个 Context 实现，其 Value 方法返回与 Gorilla 包中某个特定 HTTP 请求关联的值。

其他包也提供了类似 Context 的取消支持。例如，Tomb 提供了一个 Kill 方法，它通过关闭 Dying channel 来发出取消信号。Tomb 还提供了等待这些 goroutine 退出的方法，类似于 sync.WaitGroup。在 tomb.go 中，我们提供了一个 Context 实现，当它的父 Context 被取消或传入的 Tomb 被杀死时，该实现会被取消。

结论

在 Google，我们要求 Go 程序员在传入请求和传出请求之间的调用路径上，把 Context 参数作为每个函数的第一个参数。这使许多不同团队开发的 Go 代码能够良好地互操作。它提供了对超时和取消的简单控制，并确保安全凭证等关键值能正确地在 Go 程序中传递。

想要基于 Context 构建的服务器框架，应提供 Context 的实现，以便在它们自己的包与期望 Context 参数的包之间架起桥梁。它们的客户端库随后会从调用代码接收 Context。通过为请求级数据和取消建立通用接口，Context 让包开发者更容易共享用于构建可扩展服务的代码。
